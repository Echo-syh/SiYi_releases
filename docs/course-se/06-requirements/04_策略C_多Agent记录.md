# 策略 C · 多 Agent 交互记录

## 角色与流水线

| 阶段 | Agent 角色 | 输入 | 输出 |
| --- | --- | --- | --- |
| 1a | 用户（AI for bio 研究生） | 原始构想 | 第一人称使用叙述、痛点、弃用条件、异常经历 |
| 1b | 需求分析师 | 原始构想 | 结构化初步需求、用例、假设、风险 |
| 2 | 评审者 | 原始构想 + 1a + 1b | 按 8 条标准评审：歧义、矛盾、缺失、幻觉、过度设计 |

> 说明：三个角色由三个独立子 Agent 分别扮演，彼此不共享上下文；用户与分析师只拿到原始构想，拿不到思懿的 README 与源码。以下为各 Agent 的实际输出（逐字保存；仅对超长列表做分段，不改措辞）。

## 阶段 1a · 用户 Agent

### 提示词

```text
你扮演一位上海交通大学的研究生（机械/生物医学工程方向，在 AI for bio 课题组），
日常大量阅读英文论文。请完全以「用户」的第一人称说话，不要做需求工程术语的堆砌，
不要设计技术方案。

下面是这个软件的原始构想（只有这些，不要假设它已经存在）：
[原始构想全文]

请写出（1200–1600 字，中文）：
1. 你一周里典型的三次使用场景（新论文精读、复现前查细节、组会前回顾）；
2. 你现在的工作流里，哪些动作最烦、最容易出错、最容易丢东西；
3. 哪些功能是「没有我就不用」，哪些是「有更好」；
4. 哪些情况下你会立刻弃用它；
5. 你担心的事情：隐私、费用、数据丢失、换电脑、协作、版权；
6. 你亲身遇到过的异常情况；
7. 如果只能提三条最强烈的诉求，是哪三条？
```

### Agent 输出（逐字）

> 我现在的工位是四个窗口并排：Zotero、PDF、翻译网页、一个聊天框。一天要在它们之间切上百次，切到最后自己都想不起刚才那句话是在哪儿看到的。
>
> 周一上午精读新论文。从期刊网站下下来一个叫 1-s2.0-S009286742300xxx-main.pdf 的文件，拖进 Zotero，元数据十有八九抓错：预印本抓成会议版，作者顺序反了。打开读，双栏排版，选一段粘进聊天框，出来是被硬换行截断的句子，页眉页脚混在中间，图注插进段落，transduc- 和 tion 分成两行。模型很认真地回答了一个我没问的问题。想问公式 (2) 第三项是什么，公式复制不出来，只能截图。读到讨论卡住，想问「这个结论和 Fig. 3B 对得上吗」，聊天框看不见图，我得截图再描述「左上角那个点」。问完切回 PDF，已经翻不到原来那页。高亮在 Zotero 里，问题在聊天记录里，两边永远对不上。
>
> 周三下午复现前查细节。要跑一个 baseline，得确认数据怎么划分、counts 有没有做 log 变换、基因怎么过滤、学习率多少。正文写「按照 [23] 的方法」，[23] 又写「详见 [7]」，我开着六个 PDF 来回跳。我真正想问的是「把这几篇里关于数据划分的原话都找出来，标清楚出自哪篇哪一节」，现在只能一篇篇 Ctrl+F。更麻烦的是代码仓库 README 和论文写的不一致，我得记住哪个是哪个，通常记不住，两周后重跑发现对不上。
>
> 周四晚上组会前回顾。我记得七月读过一篇，图是一张 UMAP，方法大概是把扰动当成向量加进隐空间。在 Zotero 里搜「扰动」什么也搜不到——那篇是英文的，标签又是随手打的，一半中文一半英文。翻网页版聊天记录，标题全是「PDF 分析」「Untitled」，不能搜正文。最后按时间把七月的 PDF 一个个点开看，四十分钟没了。
>
> 最烦的三个动作：复制粘贴、每开一个新对话就重新上传一遍 PDF、找。最容易丢的三样：高亮和批注（换一版 PDF 就没了）、聊天里得出的结论、还有「我当时为什么这么判断」这句最值钱的话。笔记散在 Zotero、一个 Word 文档和聊天记录三个地方，从来没合并过。
>
> 「没有我就不用」：PDF 能打开且读得动，大文件、双栏、图都正常；AI 真的读过全文，回答能指到页码和段落，点一下跳过去；文库能导入、打标签、中英文全文搜索；所有东西在本机，断网也能读能搜。「有更好」：原文译文对照、能问图里的内容、自动抓元数据、导出 BibTeX、手机上也能看。
>
> 让我立刻弃用的瞬间：它编页码、编引文。只要有一次按它说的翻到第 7 页发现没那句话，之后它给的任何定位我都不信。第二，嘴上说本地，实际把 PDF 传到云端，哪怕只是拿扫描件去做 OCR。第三，它动我的文件——重命名、移动、改 Zotero 库，或者升级一次批注全没。第四，翻译把否定翻掉，「not significantly different」变成「显著不同」，这在方法部分会害死人。第五，偷偷用 Sci-Hub 或爬出版社，把实验室 IP 搞封。
>
> 我担心的很具体。隐私：组里未发表的 AAV 序列、投稿前的稿子、合作方给的临床数据，一样都不能出这台机器。费用：一篇长论文连补充材料几万 token，问十次就是十次钱，每次都重传全文账单很难看。数据丢失：Zotero 库损坏过一次，靠备份救回来，不想再赌。换电脑：工位台式、家里 4050 笔记本、实验室 A100 服务器，三台怎么同步，服务器还没图形界面。协作：导师想看我的笔记，我总不能发一个数据库文件。版权：出版社 PDF 不能随便传，整篇译文导出分享也有风险。
>
> 异常遇到太多。扫描版老论文没有文字层，Ctrl+F 一无所获，AI 说读不到，在线 OCR 不敢用，因为那份是合作者发来的未定稿。加密 PDF 能打开但复制被禁，选中没反应，我分不清是权限还是 bug。有次把 D:\papers 按年份重分文件夹，Zotero 里两百多条记录全成「找不到文件」，只能一条条重定位。实验室网络不稳，API 超时，流式输出停在半句，界面不报错也不保留，重试再花钱。429 和 context length 也见过，更坏的是不报错、悄悄截断，然后告诉我「文中未提及」，这比报错可怕。六十页综述加补充材料，我问第四节，它只总结了引言。中文搜索基本废掉：「脱靶」搜不到 off-target，「半衰期」搜不到 half-life，「野生型」搜不到 wild-type。表格复制出来列错位，0.87±0.03 变成 0.870.03，模型把 ± 当小数点。arXiv v1 和正式版都在库里，批注做在 v1 上，组会照着念了一个后来改掉的数字。
>
> 如果只能提三条：回答必须回到原文的具体位置，点一下能跳过去，不许编；本地优先，文件、笔记、对话、密钥都在我机器上，断网可用，联网只是增强；读、问、记、找在同一个窗口完成，两周后我还能用中文把当时问过的东西找回来。

## 阶段 1b · 分析师 Agent

### 提示词

```text
你是一位资深软件需求分析师。请只根据下面这份原始构想，产出一套结构化的
「初步软件需求」。不要参考任何现有产品实现，不要假设原始构想之外的既成事实。
[原始构想全文]

请输出（中文，1800–2200 字）：
1. 利益相关方；2. 范围与边界；3. 功能性需求（FR-01…，按模块分组，给优先级）；
4. 非功能性需求（按质量属性分组，可验证指标）；5. 假设与依赖（标注「假设」）；
6. 主要用例（至少 8 个，参与者/名称/描述/前置/后置）；7. 风险与开放问题。
要求：不写技术选型；不发明无依据的功能，必须补的标「[假设]」；避免不可度量的词。
```

### Agent 输出（逐字）

#### 1 利益相关方

- 读者（主用户）：研究者或学生，希望一个窗口完成读、问、译、存；关注回答是否基于全文、历史能否找回。决定核心交互与验收标准。
- 文库维护者（同一人的长期角色）：关注数百至数千篇下分类、标签、笔记仍可用、可备份、可迁移。决定数据模型与导入导出。
- 开发者：关注需求可验收、外部依赖可控。决定模块边界。
- 模型服务提供方（外部）：负责合规与计费；上下文长度、限流与价格约束问答和翻译。
- Windows 与设备：提供文件、账户与加密能力，决定本地存储和 key 安全的上限。
- 〔假设〕无多用户共享；若出现超出本版范围。

#### 2 范围与边界

- 范围内：本地 PDF 阅读；论文入库、分类、标签、笔记；以当前论文内容为依据的 AI 问答与对话留存；英译中及原文/译文对照；对论文、笔记、对话的本地检索；API key 本地安全保存；数据存于本机。
- 范围外：PDF 编辑与手写批注；在线检索、下载与引文插入；多端同步与云协作；本地或自建模型；扫描件 OCR；移动端与网页版。
- 职责划分：PDF 渲染、文本抽取、上下文组织、存储与检索由本系统负责；语义生成由外部模型服务负责，本系统不保证结论正确；文件权限、磁盘加密、账户隔离由 Windows 负责；网络可达性由用户网络负责。
- 〔假设〕不与 Zotero 双向同步，仅一次性导入。

#### 3 功能性需求

（未标注者为构想直接要求，〔假设〕为补充。）

**阅读**

- FR-01 打开本地 PDF，支持翻页、跳页、缩放与连续滚动。高
- FR-02 显示 PDF 目录并可点击跳转。〔假设〕中
- FR-03 同一窗口并排显示阅读区与问答区，分隔条可拖动。高
- FR-04 选中文本后就地提供「问 AI」「翻译」入口。高
- FR-05 重开同一论文时恢复上次阅读位置。〔假设〕中

**文库**

- FR-06 导入时在库目录保存副本，记录标题、作者、年份。高
- FR-07 支持多级分类与多标签，可批量修改。高
- FR-08 每篇论文可写笔记并关联该论文。高
- FR-09 删除论文可选仅移出库或同时删除文件。〔假设〕中

**问答**

- FR-10 提问以当前论文全文或相关片段为上下文，不得只传文件名。高
- FR-11 回答标注依据的页码或章节，无依据时明示「未在论文中找到」。高
- FR-12 问答自动保存，并与论文及提问页码关联。高
- FR-13 可对选中段落直接提问。高
- FR-14 同一会话支持多轮追问并保留上下文。中
- FR-15 超出上下文上限时按片段选取，界面标明「仅基于部分内容」。高

**翻译**

- FR-16 将当前页或选中段落英译中。高
- FR-17 提供逐段对齐的原文/译文对照视图。高
- FR-18 译文按页缓存并随论文保存。中

**搜索**

- FR-19 按标题、作者、标签筛选文库。高
- FR-20 跨论文正文、笔记、对话全文检索，显示命中片段，可按类型过滤并直达命中位置。高

**设置**

- FR-21 配置模型服务地址、模型名与 API key，并提供连接测试。高
- FR-22 API key 加密保存，界面与日志不明文回显。高
- FR-23 key 缺失或失效时禁用问答与翻译并说明原因。高
- FR-24 显示请求与会话累计 token 及估算费用。〔假设〕中
- FR-25 指定数据根目录，支持整库导出与导入。〔假设〕中

#### 4 非功能性需求

**性能**

- NFR-01 基准机（4 核/16GB）打开 50MB、500 页 PDF 首屏不超过 3 秒；2000 篇库内检索不超过 1 秒，全文检索不超过 5 秒。
- NFR-02 本系统附加延迟不超过 300ms；模型请求超 10 秒须显示进度并可取消。

**可靠性**

- NFR-03 异常退出重启后，已保存的笔记、标签、对话零丢失；启动自检并提示修复。
- NFR-04 请求失败自动重试不超过 2 次，仍失败保留输入可重发；100 次启动退出后条目数不变。

**易用性**

- NFR-05 新用户 5 分钟内完成「导入、提问、看到带出处回答」；5 名目标用户中 4 人无需文档完成。
- NFR-06 提问与翻译入口均不超过 2 次点击，支持自定义快捷键；界面全中文，主要按钮带文字。

**安全性**

- NFR-07 在安装目录、日志、导出包中检索 key 原文，命中数为 0。
- NFR-08 key 经操作系统用户级加密，复制到另一账户后解密失败（实测）。

**隐私**

- NFR-09 除问答与翻译外无外联；30 分钟常规使用抓包，外部地址仅限已配置的模型服务。
- NFR-10 发送前可查看内容范围，可选「仅选中段落」或「整篇」；卸载可彻底删除，执行后无残留。

**兼容性**

- NFR-11 Windows 10 1809 以上与 Windows 11 各一台实机跑通全部高优先级用例；125% 至 200% 缩放无重叠或截断。
- NFR-12 支持带文本层 PDF；加密、扫描件、损坏文件给出可读提示且不崩溃。

**可维护性**

- NFR-13 更换模型服务只改配置；导出数据带版本号，新版本能读旧版本（实测）。

**成本**

- NFR-14 会话累计 token 与估算费用实时可见；同页译文重复查看不产生新费用。

**合规**

- NFR-15 不内置论文内容，首次导入提示版权责任由用户承担；默认不采集遥测，错误上报默认关闭且逐次确认。

#### 5 假设与依赖

- A1 假设：用户自备模型服务与 key。不成立：问答与翻译不可用，产品退化为阅读器加文库，核心价值消失。
- A2 假设：论文为带文本层的英文 PDF。不成立：扫描件需 OCR、中文论文无需英译中，二者均超范围。
- A3 假设：单机单用户，库规模不超过 5000 篇。不成立：检索与索引需重做。
- A4 假设：用户接受把段落或全文发给外部模型服务，这是问答的前提。不成立：需改用本地模型，与「不上传」诉求冲突。
- A5 假设：Windows 桌面为主要阅读设备。不成立：需另建移动端并重设交互。
- D1 依赖：模型服务的可用性、上下文长度与计费，直接影响 FR-10、FR-15、FR-16 的可行性与成本。
- D2 依赖：Windows 用户级加密与文件权限；若被禁用，NFR-08 无法达成。

#### 6 主要用例

（依次为：编号｜参与者｜名称｜描述｜前置｜后置）

- UC-01 读者｜配置模型服务｜填地址、模型名、key，点测试连接看到成功｜持有可用 key｜key 加密保存，状态可用
- UC-02 读者｜导入并归档｜拖入 PDF，补标题作者，选分类打标签｜PDF 在本机｜库中新增条目，副本入库，可检索
- UC-03 读者｜边读边问｜选中段落点「问 AI」，右侧返回回答与页码｜论文已打开、服务可用｜对话保存并关联论文
- UC-04 读者｜基于全文提问｜问「方法有何局限」，系统取全文或片段作答并标注章节｜文本层可抽取｜回答与出处保存
- UC-05 读者｜对照翻译｜对当前页点翻译，原文与中文逐段对齐｜服务可用｜译文缓存，重开直接显示
- UC-06 读者｜回看历史｜在论文对话页按时间浏览、搜索关键词｜该论文有历史对话｜可跳回对应页
- UC-07 读者｜跨库找回｜输入记忆中短语，结果分列论文、笔记、对话，点击直达｜索引已建立｜只读
- UC-08 读者｜离线阅读｜断网打开已入库论文，查看已有译文与笔记｜论文已导入｜本地功能可用，问答与翻译置灰并提示
- UC-09 读者｜备份迁移｜导出整库，在另一台机器导入｜库非空｜条目、标签、笔记、对话、译文还原，key 不随包迁移

#### 7 风险与开放问题

- R1 「真的读过」的边界：长论文装不进上下文，片段检索可能漏掉关键论证，用户发现答非所问即失去信任。开放问题：允许多少「部分阅读」，是否强制逐条引用？
- R2 隐私承诺与实现矛盾：问答与翻译必然把文本发给第三方，「不上传」只对存储成立。口径不清将变成信任与合规问题。
- R3 PDF 抽取质量：双栏、公式、页眉页脚污染上下文，直接决定问答与翻译质量，却难以在需求阶段验收。开放问题：术语表是否必需？
- R4 key 与成本：泄露、额度耗尽、按量计费让用户不敢用；安全与零配置难以兼得。
- R5 与 Zotero 的关系未定：替代则迁移成本高、功能差距大，共存则双份数据。「像 Zotero 那样」若不在早期收敛，将推翻文库数据模型。

## 阶段 2 · 评审者 Agent

### 提示词

```text
你是需求评审者（评审组角色）。请对下面两段材料做一次严格评审，按课程 PPT 给的
8 条标准：中肯性、合理性、完整性、必要性、溯源性、准确性、正确性、一致性。
你的任务不是重写需求，而是找出问题并给出可执行的修改建议。

[材料一：原始构想全文]
[材料二：用户视角叙述，节选]
[材料三：分析师需求集全文]

请输出：
1. 总体结论：这套需求能不能进入下一阶段？最大的三个问题是什么？
```

### Agent 输出（逐字）

#### 一、总体结论

**不能进入下一阶段，只能进入“修订后复审”。** 按八条标准衡量，问题集中在溯源性（数字没有来源）、正确性（页码由模型生成）、一致性（A4 与原始构想冲突）、完整性（痛点未转成需求），而非条目多少。

三个最大问题：

1. **隐私承诺被降级为假设。** 原始构想的第一诉求是“不传到别人服务器”，需求集改写为“用户接受把段落或全文发给外部模型”（A4），同时把本地模型列为范围外，等于取消了 A4 不成立时的退路。R2 承认了矛盾，却没有决策人与处置方案。
2. **三条最强诉求只落实一条半。** “点一下能跳”未成为需求；“真读全文”被 FR-15 换成“按片段选取”；“不许编”没有数据来源与校验，FR-11 与 FR-15 叠加反而允许“截断后说未找到”，正是用户列出的弃用行为。
3. **用户真正抱怨的地方大多停在 R3 或范围外。** 双栏硬换行、页眉页脚、表格列错位、± 被当小数点、中文搜不到英文术语、批注丢失，都没有转成需求或给出排除理由。需求集在容易写的功能上很完整，在痛点上很空。

#### 三、无依据/幻觉清单

1. **NFR-01 的三个秒数、NFR-02 的 300ms**：无实测、无同类产品基准，属于临时估算；且 2000 篇与 A3 的 5000 篇口径不一致。
2. **NFR-05 的“5 名目标用户、4 人无需文档”**：无招募来源，利益相关方只有一人且假设单机单用户，测试对象不存在。
3. **NFR-06 的“不超过 2 次点击”与“自定义快捷键”**：用户从未提快捷键，2 次点击也无来源。
4. **FR-24“估算费用”**：FR-21 没有单价配置，费用无法产生，是典型的“看起来可验收”。
5. **FR-25 整库导出导入、FR-09 删除语义、FR-02 目录、FR-05 恢复位置**：用户叙述未提，属合理常识，但应标〔假设〕而非确定需求。
6. **NFR-15“首次导入提示版权责任由用户承担”**：用户只表达担心，提示方式与责任转移是分析师加的。
7. **验收方法过窄**：NFR-07 只搜 key 原文，漏 base64、分段、转义变体；NFR-09 用 30 分钟抓包证明“无外联”，采样证不了全称命题，且模型服务的 CDN/多域名会误报。
8. **利益相关方列“模型服务提供方”**：却没有一条需求约束其数据留存或可用性，列了等于没列。

#### 四、过度设计/方案混入清单

- FR-15“按片段选取”：检索方案，不是需求。
- FR-18“按页缓存并随论文保存”：性能实现，且与 NFR-14 的“不产生新费用”重复。
- FR-06“库目录保存副本”：存储方案（也可只存引用），且未回应“动我的文件”这条弃用条件。
- FR-22／NFR-08“操作系统用户级加密”：指定了 DPAPI 语义，需求应写“非明文、跨账户不可解”。
- FR-03“分隔条可拖动”：控件细节；用户只要求“旁边能问”。
- NFR-06“主要按钮带文字”“自定义快捷键”：视觉规范＋用户未提，且“主要按钮”不可判定。
- NFR-03“启动自检并提示修复”：功能藏在 NFR 里，修复范围与数据风险未定义。
- NFR-10“卸载无残留”：安装器行为，且与数据保留冲突。
- FR-10“不得只传文件名”：否定式实现约束，无法观测；应改为“可查看本次实际发送内容”。

#### 五、矛盾清单

1. A4 与原始构想、与“未发表数据外泄”；范围外又排除本地模型，A4 不成立时只剩退化。
2. FR-11 与 FR-15：部分覆盖时仍可能输出“未找到”。
3. FR-24 要估费，FR-21 无单价。
4. NFR-10 卸载无残留，FR-25 数据在库外。
5. NFR-01 按 2000 篇验收，A3 假设 5000 篇。
6. NFR-05 要 5 名用户，假设单机单用户。
7. 范围外排除批注，用户却最怕批注丢。
8. 职责表说文件权限归 Windows，NFR-08 又要求本系统加密 key；须写明“key 由应用、文件由系统”。
9. NFR-09“除问答翻译无外联”与 FR-21 连接测试，需注明连接测试属配置行为。

#### 六、遗漏场景清单

1. 中文搜英文术语、中文标签搜英文论文。
2. 回答点击跳转。
3. 多篇联合找原话并标篇/节。
4. 双栏硬换行、页眉页脚、公式、表格列错位、± 误判。
5. 流式中断保留半句、标记未完成。
6. 429 的退避与提示。
7. 对话命名与按论文分组（用户抱怨全是“PDF 分析”“Untitled”）。
8. 把回答沉淀为笔记（“我当时为什么这么判断”）。
9. 断网时阅读、检索、笔记仍可用的验收条目（UC-08 只有名字）。
10. 库目录被移动或重命名后的重定位（用户遇到 200 多条“找不到文件”）。
11. 加密 PDF 能打开但禁止复制。
12. 单篇笔记导出给导师。
13. arXiv v1 与正式版之间的引用/批注错位。
14. 多设备共用同一库目录时的锁与冲突（FR-25 隐含未定义）。
15. 首次建索引耗时与磁盘占用。
16. 含图论文的“问图”（用户列为“有更好”，应显式排除而非沉默）。

#### 七、两套材料的强弱判断

**用户叙述**强在场景真实、失败模式具体、有明确弃用阈值（编页码、假本地、丢批注、否定翻反、Sci-Hub），这些本身就是验收用例；弱在全是现象，没有优先级和边界，“没有就不用”与“有更好”混写，且“不外传”与“问 AI”本身也未自洽。

**需求集**强在编号骨架、职责划分、假设显式化，以及 NFR-07/08/09/14 这类可实测条款；弱在把痛感翻译成功能名词时丢了判据：“不外传”变 A4，“真读全文”变片段，“不编页码”变“标注页码”，“点一下跳”直接消失。它更像一份可开发的功能清单，而不是可验收的需求基线。

**合并建议**：保留编号体系、假设与职责表、可实测的隐私与成本条款；删掉临时估算的数字（NFR-01/02/05/11）与 UI 方案（FR-03、FR-18、NFR-06 措辞）；把 FR-10/11/15 改写为一组“可溯源回答”需求；A4 改为开放问题；补“跨语言检索”与“抽取质量”两条主线；R5 需指定决策人，否则一次性导入是否含批注、笔记、标签无法定。

#### 八、最该先补的 5 个开放问题

1. 哪些内容允许发给外部模型？全文、段落、笔记是否分级，能否关闭，模型侧留存如何处理？
2. “真的读过”如何判定：全文覆盖、片段覆盖，还是检索命中即可？截断时用户看到什么？
3. 页码与章节由谁产生、如何校验？“点一下跳”失败时如何表现？
4. 跨语言检索是本期目标还是后续？“用中文找回”的最低可保真度是什么？
5. 抽取质量的最低样例集由谁定、包含哪些真实文件？这决定 NFR-12 与 R3 能否关闭。
