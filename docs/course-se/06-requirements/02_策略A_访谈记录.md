# 策略 A · 访谈式交互记录

## 角色说明

| 角色 | 扮演者 | 说明 |
| --- | --- | --- |
| 访谈者（需求工程师） | Claude | 按通用提纲提问，不给技术方案 |
| 受访者（开发者 / 学生） | Claude | 以思懿开发者的身份回答，内容基于原始构想与项目既有事实 |

> 诚实性说明：本次作业由模型分饰两角完成访谈。受访者的回答不是凭空编造的产品功能，而是开发者对「想做成什么样」的陈述；其中一部分是已经实现的行为，一部分是当时的目标。两者在最终验证阶段会分开核对。

---

## 提示词（第 0 轮）

```text
你是一位软件需求工程师。我是这个软件的开发者，也是它的第一个用户。
请对我做一次需求访谈，遵守以下规则：

1. 一次只问一组问题，等我回答后再追问，不要一口气抛出所有问题；
2. 顺序：先问 Who / What / Why / Where / When / How，
   再问功能细节与异常边界，最后问质量属性与约束；
3. 不要替我编需求，不要给技术方案，不要假设我没说过的功能；
4. 每轮结束用 3–5 条复述你听到的需求，让我确认或纠正。

原始构想：
做一个 Windows 桌面软件，把「读论文、管文献、译文献、问 AI」放进同一个窗口。
读论文时不用在 PDF 阅读器、Zotero、翻译工具和聊天窗口之间来回切换；
问 AI 时它应该真的读过这篇论文；论文、笔记、对话都放在本机。
```

## 第 1 轮：问题与利益相关方（6W）

### 访谈者

**Q1（Who）** 这个软件给谁用？除了你还有谁？他们分别扮演什么角色？

**Q2（What）** 「读论文」在你这里具体是哪些动作？请按一次阅读的时间顺序说。

**Q3（Why）** 现在的流程最痛的是什么？请举一个具体的例子。

**Q4（Where）** 哪些东西必须在这个软件里？哪些可以留在外面？

**Q5（When）** 典型的使用时机和单次时长？

**Q6（How）** 问 AI 时，内容怎么给模型？整篇还是选段？

### 开发者

**A1** 主要是我自己。我是机械方向的学生，在 AI for bio 课题组读论文，日常要读大量英文文献。同组同学也会用；导师偶尔会看我的笔记，但不会自己装。角色上分三类：读论文的人、管文献的人、配置服务的人——实际上经常是同一个人。不会给完全不懂论文的人用。

**A2** 先找到一篇 PDF，拖进软件，补全标题作者；然后打开读，翻页、缩放、跳页，遇到不懂的段落选中问 AI；AI 回答后，把关键结论记成笔记；读完归档到某个分类。有时候还要把英文译成中文对照看。读的过程中会冒出和这篇论文无关的想法，那些记在日记里。

**A3** 最痛的是切换。PDF 在一个窗口，Zotero 在另一个，翻译在浏览器，ChatGPT 在第四个。看到一段方法描述，复制到聊天框，问完再切回来，位置还要重新找。第二个痛点是 AI 没读到正文，问「这篇的创新点」它只能泛泛而谈。第三个是过几天想找「当时问过的那句话」，得翻聊天记录，而且不知道那句话对应哪篇论文。

**A4** 论文文件、文库结构、笔记、对话、译文副本必须在里面。PDF 渲染用现成的库就行。翻译的排版重建不自己做，调本机另一个工具。文献的下载、爬取不做——版权和登录都麻烦，用户自己把 PDF 拿进来。

**A5** 三种：读新论文（30 分钟到 2 小时）、复现实验前查细节（十几分钟）、组会前快速回顾（半小时）。写综述时会连续几天高强度用。

**A6** 默认让模型能读当前论文的正文，但不是一次性全塞进去——先让它按需读页、按关键词检索，读到了再回答。用户也可以选中一段直接问。关键是回答要能指回页码，不然没法核对。

### 访谈者复述

1. 用户主要是研究者本人和同组同学，不是大众产品；导师只读笔记，不装软件。
2. 核心流程是「导入 → 阅读 → 提问 → 记笔记 → 归档」，翻译和日记是并行的两条支线。
3. 要解决的是工具切换、AI 没读到正文、问答与论文失联三个问题。
4. 软件边界：不做文献下载与爬取，不做翻译排版重建；这两件事分别留给用户和外部工具。
5. AI 必须按需读正文并给出页码依据，不能只拿文件名回答。

### 开发者确认与补充

> 对。补一条：你刚才问「导师看笔记」，那说明笔记得能拿出去。暂时不做在线分享，但至少要能导出 Markdown，不然笔记还是死在软件里。这条我刚才没说。

## 第 2 轮：功能细节与异常边界

### 访谈者

**Q7** 文库怎么组织？

**Q8** 重复导入、原文件被移走、删除条目，分别怎么处理？

**Q9** 大文件、扫描件、加密 PDF 呢？

**Q10** AI 接哪些服务商？模型怎么选？

**Q11** 流式输出、停止、崩溃，怎么处理？

**Q12** 翻译怎么做？

**Q13** 搜索范围？

**Q14** 日记和笔记的区别？

**Q15** 元数据怎么补全？

### 开发者

**A7** 分类树，能任意嵌套；一个条目可以同时属于多个分类；标签；笔记；附件。拖 PDF 进窗口就入库。也要能从 Zotero 导入已有的库，不然迁移成本太高。

**A8** 同一个 PDF 重复拖入不能变成两条；如果内容一样但文件名不同，也要能认出来。原文件被移走或删掉，条目还要在，但打开时要明确说附件丢了，并让我重新定位。删除条目时要问一句是否连附件一起删；译文副本跟着附件走。

**A9** 500 页的 PDF 要能打开，不能一开就卡死。扫描件没有文本层，AI 读不到，这种情况要明确告诉我「这篇没有可提取的文字」，而不是编一个答案。加密 PDF 打不开就给一句人话，别弹一堆异常。

**A10** 任何 OpenAI 兼容的端点都要能接，DeepSeek、智谱、MiniMax 这些；厂商和模型分两级选。key 我自己填。不同任务可能想换模型，比如读长文用便宜的，写作换个强的。

**A11** 流式输出，能随时停；思考过程可以展开看。最要命的是写到一半断电或者任务管理器强杀——重开以后那半截回答还得在，得能接着写，不能白等。

**A12** 不自研翻译。调本机跑的 zotero-pdf2zh，它能把英文 PDF 译成中文并保持排版。软件要能发现它没装/没启动，告诉我怎么装，而不是点了没反应。译好的副本存本地，关了软件再开还能看，原文/双语能切换。

**A13** 对话、文库、日记都要能搜。中文两个字就能搜到正文，不要只搜标题。Ctrl+K 打开，回车直达那一条。

**A14** 笔记绑定某篇论文/某个条目；日记是当天的想法、实验记录、组会纪要，不绑定论文。两者都要能被全局搜索搜到。

**A15** 从 PDF 首页认 DOI，去 CrossRef 补标题、作者、期刊、年份、卷期页。认不出来就手动填，不能卡住入库。不要收费的元数据服务。

### 访谈者复述

1. 文库是 Zotero 式的「分类树 + 多归属 + 标签 + 笔记 + 附件」，支持拖拽入库和 Zotero 迁移。
2. 重复导入要去重；附件丢失要可感知、可重定位；删除要区分「删条目」和「删附件」。
3. 阅读器要扛住大文件；对扫描件、加密件要给人话提示，不能假装读过。
4. AI 侧要支持任意 OpenAI 兼容端点、两级模型选择、流式、可停止、可展开思考、强杀后可恢复。
5. 翻译是外部服务依赖，软件负责发现、提示、存副本、双语对照。
6. 搜索覆盖对话/文库/日记，中文短词可命中正文；笔记与日记是两类对象，但都可搜。

### 开发者确认

> 基本对。再补两点：一是删除要有确认，不能误删；二是导入 Zotero 时对不上号的条目不要硬塞，宁可少收。

## 第 3 轮：质量属性与约束

### 访谈者

**Q16** 本地优先的边界：什么会离开本机？

**Q17** 性能指标？

**Q18** 可靠性？

**Q19** 易用性？

**Q20** 平台与安装？

**Q21** 安全？

**Q22** 约束与可行性？

### 开发者

**A16** 只有发给我配置的 LLM 服务商的内容会离开本机。界面上要能让我看到这次发了哪些页、哪些文本。API key 加密存在本机，界面上最多显示末四位。文库、笔记、对话不上传。

**A17** 启动 3 秒内；500 页 PDF 首屏 2 秒内；1 万条记录搜索 500 毫秒内；AI 首字 2 秒内（网络正常时）。这些是目标，不是现在都达到了。

**A18** 断电、强杀不能丢已经生成的内容；数据库升级失败不能把库弄坏；磁盘满要明确报错，不能静默丢数据。

**A19** 中文界面；不用看文档就能用；常用操作有快捷键；没网也能读、管、搜，只有问 AI 和翻译需要网络或本地服务。

**A20** Windows 10 及以上、64 位；安装不需要管理员权限；安装包没签名，SmartScreen 会拦，要说明怎么过；卸载不删数据，删 `%APPDATA%\siyi` 才真正清空。

**A21** 界面进程不碰文件系统、数据库和 key；所有跨进程调用走白名单；外部链接要用系统浏览器安全打开；删除数据要删干净。

**A22** 我一个人利用课余时间做；技术栈 Electron + React + TypeScript + SQLite；翻译工具是 AGPL，不能打包进安装包；进度按一个学期算；主要成本是 API 调用费。

### 访谈者复述

1. 本地优先不是「断网可用」这么简单：唯一出本机的是发给 LLM 的内容，而且发送范围必须可见。
2. 性能、可靠性、易用性都有可度量的目标；离线只覆盖读、管、搜。
3. 平台限定 Windows x64、免管理员、未签名；卸载保留数据是刻意设计。
4. 安全边界是进程隔离 + IPC 白名单 + 密钥加密 + 外链安全。
5. 单人、一学期、Electron/SQLite、AGPL 不打包，是硬约束。

### 开发者确认

> 对。另外补一条成本可见性：长论文反复问，token 烧得很快，界面上最好能让我知道这次大概花了多少，至少别让我无感地烧钱。

## 访谈结束：访谈者整理的需求轮廓

- **目标用户**：以研究者本人为主，同组同学次之；不是大众工具。
- **核心场景**：导入 → 阅读 → 就论文提问 → 记笔记 → 归档；翻译与日记为支线。
- **关键差异化**：AI 真的读到正文、回答可指回页码、问答与论文绑定。
- **边界**：不做文献下载/爬取，不做翻译排版重建，不做在线协作。
- **硬约束**：本地优先、Windows x64、单人一学期、AGPL 工具不打包。
- **访谈中新发现的需求**：笔记导出 Markdown、删除确认、Zotero 导入宁缺毋滥、token 成本可见。
