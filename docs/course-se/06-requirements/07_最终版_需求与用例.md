# 最终版 · 修订后的初步软件需求与校验用例

> 版本：v1.0（2026-10-20）
> 来源：策略 A（访谈式）与策略 C（多 Agent）两套输出合并；冲突按「原始构想 → 用户证据 → 可实现性」的顺序裁决。
> 说明：本文只写需求，不写技术方案；「实现现状」只在第 7 节作为验证证据出现，不反过来冒充需求。

---

## 1. 软件问题与解决方案

### 1.1 要解决的问题

研究者在读论文时，阅读、管理、翻译、问答分散在四个工具里，靠手工复制粘贴衔接。具体表现为：

1. **切换成本**：PDF、Zotero、翻译网页、聊天窗口来回切，读完找不到原来那页。
2. **回答失据**：AI 只拿到文件名或零散片段，回答泛泛，甚至编造页码与引文。
3. **历史失联**：问题在聊天记录里，论文在文库时，过几天想找「当时为什么这么判断」找不回来。
4. **迁移与丢失**：换电脑、移动文件夹、换 PDF 版本，批注、笔记、对话各自散落。

### 1.2 基于软件的解决方案

把「读、管、译、问、找」收进一个本地优先的 Windows 桌面应用：

- **读**：内置 PDF 阅读，支持大文件、翻页、缩放、跳页。
- **问**：AI 通过工具按需读取论文正文、按关键词检索，回答标注页码/章节；读不到就明说。
- **管**：Zotero 式文库（分类、标签、笔记、附件），导入时补全元数据。
- **译**：调用本机翻译服务，译文副本本地留存，支持原文/双语对照。
- **找**：一个入口搜对话、文库、日记，命中可直达。
- **边界**：静态数据全部留在本机；只有用户主动触发的 LLM 请求、CrossRef 查询、本机翻译服务会离开应用；发送范围可见。

### 1.3 不做什么

- 不做文献下载/爬取、不接 Sci-Hub、不内置论文内容（版权与合规）。
- 不做翻译引擎本身，只做外部服务的客户端与副本管理（AGPL 与体积约束）。
- 不做云同步、在线协作、移动端（v1；本地优先优先于同步）。
- 不做云端 OCR；扫描件只做「明确告知不可读」，是否接本地 OCR 留到 v2 评估。

### 1.4 关键裁决：本地优先与 AI 问答的边界

原始构想里有一对必须正面回答的矛盾：**「论文、笔记、对话都放在自己电脑上，不要传到别人的服务器」**，但**「问 AI 时它应该真的读过这篇论文」**。在 v1 不接本地模型的前提下，这两句话不可能同时无条件成立。

最终裁决：

1. **静态数据本地**：论文、笔记、对话、译文副本、密钥全部存本机；不上传、不云同步。
2. **AI 问答需要外发**：v1 使用用户自备的 OpenAI 兼容服务商。首次启用 AI 前，必须明确告知：发送给哪家服务商、发送哪些内容、服务商侧留存政策由服务商决定；用户确认后才启用。
3. **默认最小发送**：默认只发送当前页、选中片段或检索命中的片段；「发送整篇」必须是用户的显式选择，不得默认勾选。
4. **可查看、可关闭**：每次请求前可查看将发送的内容范围；用户可关闭 AI 功能，此时阅读、文库、搜索、笔记仍可用——这是有意设计的降级模式，不是产品失效。
5. **不碰云端 OCR、不采集遥测、不静默上传**。
6. **本地模型**列为 v2 评估项；在它落地之前，文档必须明说「完全不出本机」与「AI 问答」不可兼得，不能用「本地优先」四个字把这件事糊过去。

## 2. 范围与边界

### 2.1 范围内（v1）

本地 PDF 阅读；论文入库、分类、标签、笔记、附件；以当前论文为依据的 AI 问答与对话留存；英译中与原文/译文对照；对论文、笔记、对话的本地检索；API key 本地安全保存；数据备份与迁移。

### 2.2 范围外

| 项 | 理由 | 去向 |
| --- | --- | --- |
| 文献下载/在线检索/引文插入 | 版权、登录、反爬，且不是核心痛点 | 不做 |
| 翻译引擎与排版重建 | AGPL、体积、模型成本 | 交给本机 zotero-pdf2zh |
| 云同步/在线协作/移动端 | 与「数据在本机」冲突，单人项目做不动 | 范围外；用整库导出替代 |
| 云端 OCR | 未发表论文外泄风险 | 不做；v2 评估本地 OCR |
| PDF 标注/高亮 | 换版本易丢，且不是原始构想的核心；v1 不产生、不迁移、不管理批注，导入 Zotero 不含批注，现有批注留在 Zotero | v2；文档中明说，避免用户误以为「升级不会丢批注」 |
| 图片/公式/表格直接提问 | 需要视觉模型与版面理解；v1 的 AI 看不到图，不得假装看过 | v2；v1 在界面明确告知「当前不支持问图」 |
| 多篇论文联合提问/汇总 | v1 先把单篇问答做扎实；但用户「开六个 PDF 找原话」的诉求真实存在 | v1.1；v1 提供逐篇提问与文库检索作为替代，界面不暗示可一次问多篇 |
| 自动更新 | 未签名安装包的更新链复杂 | v2 |

### 2.3 职责划分

| 能力 | 由谁负责 |
| --- | --- |
| PDF 渲染、文本抽取、上下文组织、存储、检索 | 本软件 |
| 语义生成、翻译质量 | 外部 LLM / 本机翻译服务；本软件不保证其正确性，只负责边界与提示 |
| 文件权限、磁盘加密、账户隔离 | Windows |
| 网络可达性、API 额度 | 用户与网络环境 |

## 4. 功能性需求（v1）

> 优先级：高 = 没有它核心流程不成立；中 = 显著影响体验；低 = 可延后。
> 来源：A = 访谈；C = 多 Agent；U = 用户视角；I = 实现核对中发现的缺口。

| ID | 需求 | 优先级 | 来源 |
| --- | --- | --- | --- |
| FR-01 | 用户可打开本机 PDF，进行翻页、跳页、缩放、连续滚动；500 页级文件不得卡死界面。 | 高 | A/C |
| FR-02 | 阅读与问答可在同一窗口协作完成；具体布局（并排/切换/可拖动）不作规定。 | 高 | A/C |
| FR-03 | 重新打开同一论文时，恢复上次阅读位置（v1.1 可延后，发布说明须标注）。 | 中（v1.1 可延后） | C |
| FR-04 | 用户可选中 PDF 中的文本片段直接提问；问题、片段、回答三者可追溯。 | 高 | A/C |
| FR-05 | AI 回答必须基于实际读取的论文内容；回答所依据的页/片段必须可查看；不得只给文件名或摘要就冒充全文。 | 高 | A/C/U |
| FR-06 | 引用页码/章节只能来自抽取层的页-段映射或工具返回结果；模型自报的页码不得直接展示为可跳转引用；系统校验失败时显示「无法定位」，不得伪装成链接。 | 高 | A/C/U |
| FR-07 | 回答状态三态：全文覆盖 / 部分覆盖 / 未找到。部分覆盖须标注已读页码范围，并禁止输出「论文没有提到」；未找到只能表述为「在已读的 X–Y 页中未找到」。 | 高 | C/U/I |
| FR-08 | 同一阅读会话支持多轮追问并保留上下文；会话与论文绑定；会话自动命名并可编辑，支持按论文/时间筛选，避免大量 Untitled/「PDF 分析」。 | 中 | C/A/U |
| FR-09 | 对扫描件（无文本层）、加密 PDF、损坏 PDF：明确告知不可读及原因，不得编造内容；加密但禁止复制的文件须说明是权限限制而非故障；不默认上传云端 OCR。 | 高 | A/C/U |
| FR-10 | 支持拖拽或选择导入 PDF，建立条目与附件；尝试从首页识别 DOI 并经 CrossRef 补全元数据；补全失败或低置信时保留空值/原值，不得写入错误元数据；可手填，不阻塞入库。 | 高 | A/C |
| FR-11 | 重复导入同一 PDF（含文件名不同、内容相同）不得产生重复条目，以内容哈希判重；同一论文的不同版本（arXiv v1/正式版）不合并，条目可标注版本。 | 中 | A/I/U |
| FR-12 | 文库支持多级分类、条目多分类归属、标签、笔记、附件；多分类必须在界面上可操作，不能只有数据层。 | 高 | A/C/I |
| FR-13 | 附件生命周期：原文件被移动/删除时条目保留并提示，可重新定位；库目录整体移动/重命名后支持批量重定位；删除分「移出文库/软删除」与「彻底删除」；彻底删除须同时清理磁盘文件与译文副本；支持回收站恢复；v1 不产生、不迁移 PDF 批注，导入 Zotero 不含批注。 | 高 | A/C/I/U |
| FR-14 | Zotero 迁移：v1 只做源数据预检与 skipped 报告，不自动导入；数据合格且用户确认后，再提供一次性导入（v1.1）。 | 低 | A/I |
| FR-15 | 笔记绑定条目，支持 Markdown 编辑与预览；可导出 Markdown；AI 回答可一键保存为笔记，并自动带论文与页码来源。 | 中 | A/C/U |
| FR-16 | 日记不绑定具体论文，用于记录想法/实验/组会；与笔记一样可被全局搜索。 | 中 | A |
| FR-17 | 全局搜索覆盖对话、文库、日记；≥2 字中文查询可命中正文；至少验收 脱靶/off-target、半衰期/half-life、野生型/wild-type 三组中英互搜；结果显示来源并可直接打开对应对象；若只按原文词检索，界面须明示，不得假装支持。 | 高 | A/C/U |
| FR-18 | 论文翻译调用本机 zotero-pdf2zh；支持服务发现、地址配置、未启动指引；译文副本本地留存、离线可读；支持原文/双语切换；译文由外部服务生成，软件不保证正确，对否定/数值/专名三类抽样验收；失败或空结果须明确提示，用户可标记问题。 | 中 | A/C/U |
| FR-19 | 支持任意 OpenAI 兼容服务商；厂商与模型两级选择；提供连接测试；key 缺失/失效时禁用问答并说明原因。 | 高 | A/C |
| FR-20 | API key 加密存储；界面、日志、导出包均不得出现明文；界面最多显示末四位。 | 高 | A/C |
| FR-21 | 显示每次请求与会话累计的 token 用量；费用估算需用户配置单价，未配置时只显示 token，不编造金额；长论文重复提问时给出成本提示。 | 中 | A/C/U |
| FR-22 | 首次启用 AI 前明确告知发送对象、内容范围、服务商留存政策由服务商决定，用户确认后才启用；默认只发送当前页/选中片段/检索命中片段，整篇发送须用户显式选择；每次请求前可查看将发送的内容；明确「本地优先」边界：静态数据在本机，离开本机的只有 LLM 请求、CrossRef 查询、本机翻译服务。 | 高 | A/C/U/I |
| FR-23 | 生成过程流式展示、可停止、思考过程可展开；429 单独退避并提示；进程被强杀/断电后重启，半截回答保留、标记「未完成」且可继续；同一时刻只允许一个实例。 | 高 | A/C/I |
| FR-24 | 支持指定数据根目录、整库导出/导入（含条目、标签、笔记、对话、译文，不含 key）；同一数据目录只允许一个实例写入，检测到锁冲突时只读或提示；卸载保留数据；彻底删除只清理配置的根目录。 | 中（v1 最后一项） | C/U/I |

## 6. 校验用例

> 每个用例给出：参与者、名称、描述、前置条件、后置条件。交互步骤只列关键分支，不展开界面细节。

### UC-01 导入论文

- **参与者**：读者
- **描述**：读者拖入或选择 PDF，系统建立条目与附件，尝试补全元数据；重复文件不重复入库。
- **前置条件**：软件已启动；PDF 在本机且可读；文件不超过大小上限。
- **后置条件**：条目与附件入库；元数据已补全或标记待补；重复文件被识别并提示；失败时给出原因且不产生半条记录。

### UC-02 组织文库

- **参与者**：读者
- **描述**：建立多级分类，把条目放入一个或多个分类，打标签，写笔记，管理附件。
- **前置条件**：文库中有条目。
- **后置条件**：分类/标签/笔记/多分类归属持久化；界面可完成多分类操作；条目可被检索。

### UC-03 阅读 PDF

- **参与者**：读者
- **描述**：打开条目附件，翻页、跳页、缩放、连续滚动；重开时恢复上次位置。
- **前置条件**：条目有可用附件。
- **后置条件**：页面正确渲染；大文件不卡死；附件丢失时提示并可重新定位。

### UC-04 就论文提问

- **参与者**：读者、LLM 服务商（外部系统）
- **描述**：读者在阅读界面提问；模型按需读取当前论文的页/检索全文；回答标注页码或章节；只读到部分内容时明确标注。
- **前置条件**：已打开论文；已配置可用服务商与密钥；论文有可提取文本。
- **后置条件**：回答与论文/会话绑定；引用可定位；未读到的内容不被说成「不存在」；部分阅读有标注。

### UC-05 选中片段提问

- **参与者**：读者、LLM 服务商
- **描述**：选中一段文字，就这段文字提问；回答与片段可追溯。
- **前置条件**：PDF 有文本层；已选中文本。
- **后置条件**：回答针对片段；片段、问题、回答三者关联保存。

### UC-06 中断后继续生成

- **参与者**：读者
- **描述**：生成被停止、强杀或断电中断；重启后恢复半截内容并继续。
- **前置条件**：应用曾在中途退出；数据库中有未完成的助手消息。
- **后置条件**：半截回答仍在；可继续生成；不重放已成功的工具调用；清扫不误删内容。

### UC-07 翻译论文

- **参与者**：读者、本机翻译服务（外部系统）
- **描述**：调用本机 zotero-pdf2zh 翻译当前论文；译文本地留存；支持原文/双语切换；服务不可用/失败/空结果有明确提示。
- **前置条件**：已打开论文且论文已入库；翻译服务可用；已配置翻译后端。
- **后置条件**：译文副本存本地并可离线打开；重复查看不重复翻译/计费；失败不假装成功。

### UC-08 全局搜索

- **参与者**：读者
- **描述**：通过快捷键唤起搜索，覆盖对话、文库、日记；中文短词可命中正文；结果显示来源并直达。
- **前置条件**：已有对话/文库/日记数据；索引已建立。
- **后置条件**：命中项高亮；回车打开对应对象；无结果时明确「未找到」而非空白。

### UC-09 记笔记并导出

- **参与者**：读者
- **描述**：在条目下写 Markdown 笔记，预览、保存、导出。
- **前置条件**：已打开条目。
- **后置条件**：笔记绑定条目并持久化；导出的 Markdown 可被外部编辑器打开。

### UC-10 写日记

- **参与者**：读者
- **描述**：记录不绑定论文的想法、实验记录、组会纪要。
- **前置条件**：软件已启动。
- **后置条件**：日记保存；可被全局搜索命中；与笔记在数据与界面上可区分。

### UC-11 配置服务商与密钥

- **参与者**：读者（管理员）
- **描述**：填写 OpenAI 兼容端点、密钥，选择厂商与模型，测试连通性。
- **前置条件**：持有服务商 endpoint 与 key。
- **后置条件**：配置保存；密钥加密，界面/日志仅末四位；连接失败有分类原因；key 失效时问答入口禁用并说明。

### UC-12 删除与恢复

- **参与者**：读者
- **描述**：把条目移出文库（软删除）、从回收站恢复、或彻底删除。
- **前置条件**：条目存在。
- **后置条件**：软删除可恢复；彻底删除须确认，并清理数据库记录、磁盘附件、译文副本；删除后无残留。

### UC-13 备份与迁移

- **参与者**：读者
- **描述**：导出整库，在另一台机器导入；key 不随包迁移。
- **前置条件**：库非空；目标机器已安装同版本或更新版本。
- **后置条件**：条目、分类、标签、笔记、对话、译文还原；版本号校验；旧版本数据可被新版本读取；key 需重新配置。

### UC-14 处理不可读 PDF

- **参与者**：读者
- **描述**：打开扫描件、加密件或损坏件；系统明确告知不可读及原因，不编造内容，不默认上传 OCR。
- **前置条件**：文件已导入或已选择。
- **后置条件**：用户看到可理解的提示与下一步建议（换文件/解密/本地 OCR 待评估）；问答与翻译入口对不可读文件禁用并说明。

### 7.3 可行性分析

| 维度 | 结论 | 依据 |
| --- | --- | --- |
| 技术 | 可行 | Electron/React/TypeScript/SQLite/PDF.js 均为成熟技术；AI 走 OpenAI 兼容协议；翻译走本机 HTTP。主要风险是 PDF 抽取质量与上下文长度，不是框架 |
| 设备 | 可行 | Windows 10+ x64、免管理员；不需要 GPU；翻译服务另装，体积与 AGPL 问题隔离 |
| 进度 | 偏紧 | 单人一学期；v1 的 24 条 FR 需要取舍。建议先做 P0：阅读、提问、文库、搜索；备份/恢复、跨文献汇总放 v1.1 |
| 成本 | 可控 | CrossRef 免费；API 按量计费由用户承担；无服务器成本；翻译服务用户自装 |
| 商业 | 不适用 | 个人/课题组工具，不以盈利为目标；价值用「省下的切换与查找时间」衡量，未做市场验证 |
| 社会/合规 | 需注意 | 不下载版权文献、不接 Sci-Hub；AGPL 工具不打包；未发表数据默认不出本机；首次导入提示版权责任 |

### 7.4 评审结论

**有条件通过。** 需求可以作为 v1 的基线，但必须先把三件事说死：

1. **「读过」的判据**：读了多少页、是否截断、引用能否定位，必须在界面上可见。
2. **本地优先的边界**：哪些内容会发给 LLM、何时发、发多少，必须可查看；「不上传」只对静态存储成立。
3. **删除的语义**：软删除、彻底删除、译文副本、磁盘文件，四者必须一致，不能出现「界面删了、磁盘还在」。

### 7.5 对策略 C 初版的评审结论（原样保留）

评审者对分析师初版的结论是 **「不能进入下一阶段，只能进入修订后复审」**。三个最大问题：

1. **隐私承诺被降级为假设**：原始构想的第一诉求是「不传到别人服务器」，初版把它改写成「用户接受把段落或全文发给外部模型」的假设 A4，同时把本地模型列为范围外，等于取消了不成立时的退路。
2. **三条最强诉求只落实一条半**：「点一下能跳」没有成为需求；「真读全文」被「按片段选取」替换；「不许编」没有校验，FR-11 与 FR-15 叠加反而允许「截断后说未找到」。
3. **用户真正抱怨的地方大多停在风险或范围外**：双栏硬换行、页眉页脚、表格列错位、± 被当小数点、中文搜不到英文术语、批注丢失，都没有转成需求。

这次评审直接改动了最终版的五处：

- 新增 1.4「本地优先与 AI 问答的边界」，把 A4 从假设改成显式裁决；
- FR-05/06/07 改为「三态 + 引用来源校验」；
- FR-17 增加中英互搜的三组验收样例；
- NFR-15 增加抽取质量样本集；
- FR-13/15/18 补批注边界、回答沉淀为笔记、译文质量抽检。

这也说明：**AI 评审 AI 有用，但前提是评审者拿到的是「原始构想 + 用户证据」，而不是分析师自己的措辞。** 如果只让评审者看需求文档，它会顺着文档内部逻辑挑毛病，挑不出「需求已经把用户的诉求改写掉了」这类问题。

## 8. 风险与开放问题

| # | 风险/开放问题 | 影响 | 当前处理 |
| --- | --- | --- | --- |
| R1 | 长论文装不进上下文，片段检索可能漏掉关键论证 | 回答失据，用户失去信任 | FR-07 要求标注部分阅读；FR-06 要求引用可定位；v1.1 评估更好的检索 |
| R2 | 「本地优先」与「发给 LLM」的口径冲突 | 信任与合规风险 | FR-22 明确边界；发送范围可见；不默认云端 OCR |
| R3 | PDF 抽取质量（双栏、公式、页眉页脚、表格） | 问答与翻译质量不可控 | 验收加入固定样本；抽取失败必须可见，不得静默 |
| R4 | 外部翻译服务的质量与可用性 | 译文错误、服务不可用 | 软件只做客户端与提示；否定/数值/术语抽样验收；失败不假装成功 |
| R5 | 单人一学期做不完 24 条 FR | 延期或砍功能 | 版本分层；P0 先做阅读/提问/文库/搜索 |
| R6 | 多设备/协作诉求被列为范围外 | 用户可能失望 | 用整库导出/导入替代；在文档中写明取舍，不装作支持 |
| R7 | Zotero 迁移的数据质量不可控 | 导入后文库不可用 | 预检 + 跳过报告；不合格时不导入；降级 v1.1 |
