# 一、策略 A：访谈式

## 1.1 提示词

```text
你是一位软件需求工程师。我是这个软件的开发者，也是它的第一个用户。
请对我做一次需求访谈，遵守以下规则：

1. 一次只问一组问题，等我回答后再追问，不要一口气抛出所有问题；
2. 顺序：先问 Who / What / Why / Where / When / How，
   再问功能细节与异常边界，最后问质量属性与约束；
3. 不要替我编需求，不要给技术方案，不要假设我没说过的功能；
4. 每轮结束用 3–5 条复述你听到的需求，让我确认或纠正。

原始构想：
做一个 Windows 桌面软件，把「读论文、管文献、译文献、问 AI」放进同一个窗口。
读论文时不用在 PDF 阅读器、Zotero、翻译工具和聊天窗口之间来回切换；
问 AI 时它应该真的读过这篇论文；论文、笔记、对话都放在本机。
```

## 1.2 第一轮：问题与利益相关方（6W）

**问：这个软件给谁用？除了你还有谁？他们分别扮演什么角色？**

答：主要是我自己。我是机械方向的学生，在 AI for bio 课题组读论文，日常要读大量英文文献。同组同学也会用；导师偶尔会看我的笔记，但不会自己装。角色上分三类：读论文的人、管文献的人、配置服务的人——实际上经常是同一个人。不会给完全不懂论文的人用。

**问：「读论文」在你这里具体是哪些动作？请按一次阅读的时间顺序说。**

答：先找到一篇 PDF，拖进软件，补全标题作者；然后打开读，翻页、缩放、跳页，遇到不懂的段落选中问 AI；AI 回答后，把关键结论记成笔记；读完归档到某个分类。有时候还要把英文译成中文对照看。读的过程中会冒出和这篇论文无关的想法，那些记在日记里。

**问：现在的流程最痛的是什么？请举一个具体的例子。**

答：最痛的是切换。PDF 在一个窗口，Zotero 在另一个，翻译在浏览器，ChatGPT 在第四个。看到一段方法描述，复制到聊天框，问完再切回来，位置还要重新找。第二个痛点是 AI 没读到正文，问「这篇的创新点」它只能泛泛而谈。第三个是过几天想找「当时问过的那句话」，得翻聊天记录，而且不知道那句话对应哪篇论文。

**问：哪些东西必须在这个软件里？哪些可以留在外面？**

答：论文文件、文库结构、笔记、对话、译文副本必须在里面。PDF 渲染用现成的库就行。翻译的排版重建不自己做，调本机另一个工具。文献的下载、爬取不做——版权和登录都麻烦，用户自己把 PDF 拿进来。

**问：典型的使用时机和单次时长？**

答：三种：读新论文（30 分钟到 2 小时）、复现实验前查细节（十几分钟）、组会前快速回顾（半小时）。写综述时会连续几天高强度用。

**问：问 AI 时，内容怎么给模型？整篇还是选段？**

答：默认让模型能读当前论文的正文，但不是一次性全塞进去——先让它按需读页、按关键词检索，读到了再回答。用户也可以选中一段直接问。关键是回答要能指回页码，不然没法核对。

**访谈者复述**：用户主要是研究者本人和同组同学，不是大众产品；核心流程是导入 → 阅读 → 提问 → 记笔记 → 归档；要解决工具切换、AI 没读到正文、问答与论文失联；软件边界是不做文献下载与爬取、不做翻译排版重建；AI 必须按需读正文并给出页码依据。

**开发者补充**：导师看笔记，说明笔记得能拿出去。暂时不做在线分享，但至少要能导出 Markdown。

## 1.3 第二轮：功能细节与异常边界

**问：文库怎么组织？**

答：分类树，能任意嵌套；一个条目可以同时属于多个分类；标签；笔记；附件。拖 PDF 进窗口就入库。也要能从 Zotero 导入已有的库，不然迁移成本太高。

**问：重复导入、原文件被移走、删除条目，分别怎么处理？**

答：同一个 PDF 重复拖入不能变成两条；如果内容一样但文件名不同，也要能认出来。原文件被移走或删掉，条目还要在，但打开时要明确说附件丢了，并让我重新定位。删除条目时要问一句是否连附件一起删；译文副本跟着附件走。

**问：大文件、扫描件、加密 PDF 呢？**

答：500 页的 PDF 要能打开，不能一开就卡死。扫描件没有文本层，AI 读不到，这种情况要明确告诉我「这篇没有可提取的文字」，而不是编一个答案。加密 PDF 打不开就给一句人话，别弹一堆异常。

**问：AI 接哪些服务商？模型怎么选？**

答：任何 OpenAI 兼容的端点都要能接，DeepSeek、智谱、MiniMax 这些；厂商和模型分两级选。key 我自己填。不同任务可能想换模型，比如读长文用便宜的，写作换个强的。

**问：流式输出、停止、崩溃，怎么处理？**

答：流式输出，能随时停；思考过程可以展开看。最要命的是写到一半断电或者任务管理器强杀——重开以后那半截回答还得在，得能接着写，不能白等。

**问：翻译怎么做？**

答：不自研翻译。调本机跑的 zotero-pdf2zh，它能把英文 PDF 译成中文并保持排版。软件要能发现它没装/没启动，告诉我怎么装，而不是点了没反应。译好的副本存本地，关了软件再开还能看，原文/双语能切换。

**问：搜索范围？**

答：对话、文库、日记都要能搜。中文两个字就能搜到正文，不要只搜标题。Ctrl+K 打开，回车直达那一条。

**问：日记和笔记的区别？**

答：笔记绑定某篇论文/某个条目；日记是当天的想法、实验记录、组会纪要，不绑定论文。两者都要能被全局搜索搜到。

**问：元数据怎么补全？**

答：从 PDF 首页认 DOI，去 CrossRef 补标题、作者、期刊、年份、卷期页。认不出来就手动填，不能卡住入库。不要收费的元数据服务。

**开发者补充**：删除要有确认，不能误删；导入 Zotero 时对不上号的条目不要硬塞，宁可少收。

## 1.4 第三轮：质量属性与约束

**问：本地优先的边界：什么会离开本机？**

答：只有发给我配置的 LLM 服务商的内容会离开本机。界面上要能让我看到这次发了哪些页、哪些文本。API key 加密存在本机，界面上最多显示末四位。文库、笔记、对话不上传。

**问：性能指标？**

答：启动 3 秒内；500 页 PDF 首屏 2 秒内；1 万条记录搜索 500 毫秒内；AI 首字 2 秒内（网络正常时）。这些是目标，不是现在都达到了。

**问：可靠性？**

答：断电、强杀不能丢已经生成的内容；数据库升级失败不能把库弄坏；磁盘满要明确报错，不能静默丢数据。

**问：易用性？**

答：中文界面；不用看文档就能用；常用操作有快捷键；没网也能读、管、搜，只有问 AI 和翻译需要网络或本地服务。

**问：平台与安装？**

答：Windows 10 及以上、64 位；安装不需要管理员权限；安装包没签名，SmartScreen 会拦，要说明怎么过；卸载不删数据，删 `%APPDATA%\siyi` 才真正清空。

**问：安全？**

答：界面进程不碰文件系统、数据库和 key；所有跨进程调用走白名单；外部链接要用系统浏览器安全打开；删除数据要删干净。

**问：约束与可行性？**

答：我一个人利用课余时间做；技术栈 Electron + React + TypeScript + SQLite；翻译工具是 AGPL，不能打包进安装包；进度按一个学期算；主要成本是 API 调用费。

**开发者补充**：长论文反复问，token 烧得很快，界面上最好能让我知道这次大概花了多少，至少别让我无感地烧钱。

# 二、策略 C：多 Agent

## 2.1 三个角色的提示词

**用户 Agent**

```text
你扮演一位上海交通大学的研究生（机械/生物医学工程方向，在 AI for bio 课题组），
日常大量阅读英文论文。请完全以「用户」的第一人称说话，不要做需求工程术语的堆砌，
不要设计技术方案。下面是这个软件的原始构想（只有这些，不要假设它已经存在）：
[原始构想全文]
请写出：三次典型使用场景；最烦/最易错/最易丢的动作；「没有就不用」与「有更好」；
弃用条件；隐私/费用/数据/换机/协作/版权担忧；亲历的异常；三条最强诉求。
```

**分析师 Agent**

```text
你是一位资深软件需求分析师。请只根据下面这份原始构想，产出一套结构化的
「初步软件需求」。不要参考任何现有产品实现，不要假设原始构想之外的既成事实。
[原始构想全文]
输出：利益相关方；范围与边界；功能性需求（FR-01…，按模块分组，给优先级）；
非功能性需求（按质量属性分组，可验证指标）；假设与依赖（标注「假设」）；
主要用例（至少 8 个，参与者/名称/描述/前置/后置）；风险与开放问题。
要求：不写技术选型；不发明无依据的功能，必须补的标「[假设]」；避免不可度量的词。
```

**评审者 Agent**

```text
你是需求评审者。请按课程 PPT 的 8 条标准——中肯性、合理性、完整性、必要性、
溯源性、准确性、正确性、一致性——评审下面的材料。你的任务不是重写需求，
而是找出问题并给出可执行的修改建议。
[材料一：原始构想；材料二：用户视角叙述；材料三：分析师需求集]
输出：总体结论；逐条问题表（位置/类型/严重度/理由/修改建议，至少 15 条）；
无依据/幻觉清单；过度设计清单；矛盾清单；遗漏场景清单（至少 10 条）；
两套材料的强弱判断与合并建议；最该先补的 5 个开放问题。
不要重写需求全文；不要引入新的技术方案；不要替分析师圆场。
```

## 2.2 用户 Agent 的输出（节选）

> 我现在的工位是四个窗口并排：Zotero、PDF、翻译网页、一个聊天框。一天要在它们之间切上百次，切到最后自己都想不起刚才那句话是在哪儿看到的。
>
> 周一上午精读新论文。从期刊网站下下来一个叫 1-s2.0-S009286742300xxx-main.pdf 的文件，拖进 Zotero，元数据十有八九抓错：预印本抓成会议版，作者顺序反了。打开读，双栏排版，选一段粘进聊天框，出来是被硬换行截断的句子，页眉页脚混在中间，图注插进段落，transduc- 和 tion 分成两行。模型很认真地回答了一个我没问的问题。想问公式 (2) 第三项是什么，公式复制不出来，只能截图。读到讨论卡住，想问「这个结论和 Fig. 3B 对得上吗」，聊天框看不见图，我得截图再描述「左上角那个点」。问完切回 PDF，已经翻不到原来那页。高亮在 Zotero 里，问题在聊天记录里，两边永远对不上。
>
> 周三下午复现前查细节。要跑一个 baseline，得确认数据怎么划分、counts 有没有做 log 变换、基因怎么过滤、学习率多少。正文写「按照 [23] 的方法」，[23] 又写「详见 [7]」，我开着六个 PDF 来回跳。我真正想问的是「把这几篇里关于数据划分的原话都找出来，标清楚出自哪篇哪一节」，现在只能一篇篇 Ctrl+F。
>
> 周四晚上组会前回顾。我记得七月读过一篇，图是一张 UMAP，方法大概是把扰动当成向量加进隐空间。在 Zotero 里搜「扰动」什么也搜不到——那篇是英文的，标签又是随手打的，一半中文一半英文。翻网页版聊天记录，标题全是「PDF 分析」「Untitled」，不能搜正文。最后按时间把七月的 PDF 一个个点开看，四十分钟没了。
>
> 最烦的三个动作：复制粘贴、每开一个新对话就重新上传一遍 PDF、找。最容易丢的三样：高亮和批注（换一版 PDF 就没了）、聊天里得出的结论、还有「我当时为什么这么判断」这句最值钱的话。
>
> 让我立刻弃用的瞬间：它编页码、编引文。只要有一次按它说的翻到第 7 页发现没那句话，之后它给的任何定位我都不信。第二，嘴上说本地，实际把 PDF 传到云端，哪怕只是拿扫描件去做 OCR。第三，它动我的文件——重命名、移动、改 Zotero 库，或者升级一次批注全没。第四，翻译把否定翻掉，「not significantly different」变成「显著不同」。第五，偷偷用 Sci-Hub 或爬出版社。
>
> 如果只能提三条：回答必须回到原文的具体位置，点一下能跳过去，不许编；本地优先，文件、笔记、对话、密钥都在我机器上，断网可用；读、问、记、找在同一个窗口完成，两周后我还能用中文把当时问过的东西找回来。

## 2.3 分析师 Agent 的输出（摘要）

- **利益相关方**：读者、文库维护者、开发者、模型服务提供方、Windows 与设备；假设无多用户共享。
- **范围外**：PDF 编辑与手写批注、在线检索/下载/引文插入、多端同步/云协作、本地或自建模型、扫描件 OCR、移动端/网页版。
- **功能性需求**：25 条，分阅读（FR-01–05）、文库（FR-06–09）、问答（FR-10–15）、翻译（FR-16–18）、搜索（FR-19–20）、设置（FR-21–25）。
- **非功能性需求**：15 条，覆盖性能、可靠性、易用性、安全、隐私、兼容性、可维护性、成本、合规。
- **假设**：A1 用户自备模型服务与 key；A2 论文为带文本层英文 PDF；A3 单机单用户、库不超过 5000 篇；A4 用户接受把段落或全文发给外部模型；A5 Windows 桌面为主要阅读设备。
- **用例**：9 个（配置服务、导入归档、边读边问、基于全文提问、对照翻译、回看历史、跨库找回、离线阅读、备份迁移）。
- **风险**：R1「真的读过」的边界；R2 隐私承诺与实现矛盾；R3 PDF 抽取质量；R4 key 与成本；R5 与 Zotero 的关系未定。

## 2.4 评审者 Agent 的结论（逐字）

**总体结论：不能进入下一阶段，只能进入“修订后复审”。** 问题集中在溯源性（数字没有来源）、正确性（页码由模型生成）、一致性（A4 与原始构想冲突）、完整性（痛点未转成需求），而非条目多少。

三个最大问题：

1. **隐私承诺被降级为假设。** 原始构想的第一诉求是“不传到别人服务器”，需求集改写为“用户接受把段落或全文发给外部模型”（A4），同时把本地模型列为范围外，等于取消了 A4 不成立时的退路。
2. **三条最强诉求只落实一条半。** “点一下能跳”未成为需求；“真读全文”被 FR-15 换成“按片段选取”；“不许编”没有数据来源与校验，FR-11 与 FR-15 叠加反而允许“截断后说未找到”。
3. **用户真正抱怨的地方大多停在 R3 或范围外。** 双栏硬换行、页眉页脚、表格列错位、± 被当小数点、中文搜不到英文术语、批注丢失，都没有转成需求或给出排除理由。

评审者列出的主要问题（按严重度）：

| 位置 | 问题 | 严重度 | 修改建议 |
| --- | --- | --- | --- |
| 假设 A4 / 范围 | 矛盾 | 高 | 改为开放问题；定发送边界、首次告知、模型侧留存；A4 不得默认成立 |
| FR-11 / FR-15 | 一致性 | 高 | 合成三态：全文覆盖/部分覆盖/未找到；部分覆盖禁止输出“未找到” |
| FR-11 | 缺失 | 高 | 增加依据可点击定位到页/段，并定义定位失败时的表现 |
| FR-11 | 正确性 | 高 | 定位只能引用抽取层的段落—页码映射，模型不得自报页码 |
| FR-20 | 缺失 | 高 | 补中英互搜验收样例，至少覆盖脱靶/off-target 等三组 |
| FR-10 | 缺失 | 高 | 明确是否支持多篇联合提问；不做则写入范围外并给替代路径 |
| NFR-12 / R3 | 缺失 | 高 | 建抽取质量样例集，否则“支持带文本层 PDF”不可验收 |
| FR-16 / FR-17 | 缺失 | 高 | 加否定、数字、专名抽检；译文可编辑或可标错 |
| FR-15 | 过度设计 | 高 | 改为结果约束：覆盖全文或明示未覆盖范围 |
| NFR-01/02/05/11 | 无依据 | 高 | 标来源或改为相对目标；统一库规模；写明测试机 |
| FR-06 | 歧义 | 中 | 定来源优先级，允许手工纠正，抓取失败不得写错值 |
| FR-24 / FR-21 | 不一致 | 中 | 增单价配置，或改为只显示 token |
| NFR-10 / FR-25 | 矛盾 | 中 | 区分程序与数据；卸载默认保留，另设清除 |
| 范围外“批注” | 范围错位 | 中 | 写明排除理由与用户可见说明；导入 Zotero 批注需单列 |
| NFR-02 / NFR-04 | 缺失 | 中 | 加中断保留已生成部分、标记未完成、可续写；429 单独退避 |

评审者还列了 16 条遗漏场景，包括：中文搜英文术语、回答点击跳转、多篇联合找原话、双栏/页眉页脚/公式/表格/±、流式中断、429、对话命名与按论文分组、回答沉淀为笔记、断网时读/搜/记、库目录移动后的重定位、加密 PDF 禁止复制、笔记导出、arXiv v1 与正式版错位、多设备共用目录的锁、首次建索引、问图。

# 四、最终版需求（24 FR / 16 NFR / 14 UC）

## 4.1 功能性需求

| ID | 需求 | 优先级 |
| --- | --- | --- |
| FR-01 | 打开本机 PDF，翻页、跳页、缩放、连续滚动；500 页级文件不得卡死界面。 | 高 |
| FR-02 | 阅读与问答可在同一窗口协作完成；具体布局不作规定。 | 高 |
| FR-03 | 重新打开同一论文时恢复上次阅读位置。 | 中 |
| FR-04 | 选中文本片段直接提问；问题、片段、回答三者可追溯。 | 高 |
| FR-05 | AI 回答基于实际读取的论文内容；回答依据的页/片段必须可查看；不得只给文件名或摘要冒充全文。 | 高 |
| FR-06 | 引用页码/章节只能来自抽取层页-段映射或工具结果；模型自报页码不得直接作为可跳转引用；无法定位时明示。 | 高 |
| FR-07 | 回答状态三态：全文覆盖/部分覆盖/未找到；部分覆盖须标已读范围，禁止输出「论文没有提到」。 | 高 |
| FR-08 | 多轮追问保留上下文；会话与论文绑定；自动命名、可编辑、按论文/时间筛选。 | 中 |
| FR-09 | 扫描件/加密/损坏 PDF 明确告知不可读及原因；不得编造；不默认上传云端 OCR。 | 高 |
| FR-10 | 拖拽/选择导入 PDF；DOI→CrossRef 补全；失败或低置信不写错值；可手填。 | 高 |
| FR-11 | 重复导入按内容哈希去重；不同版本不合并，可标注版本。 | 中 |
| FR-12 | 多级分类、条目多分类、标签、笔记、附件；多分类必须在界面上可操作。 | 高 |
| FR-13 | 附件丢失提示与重定位；库目录整体移动后批量重定位；软删除/恢复/彻底删除；彻底删除清磁盘与译文；v1 不产生/不迁移批注。 | 高 |
